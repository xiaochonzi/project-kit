# 验证规则

## 新鲜证据原则

任何完成声明必须紧邻本轮实际运行的命令或人工检查。旧日志、他人声明、代码看起来正确、测试“应该会过”都不是完成证据。

## 证据层级

优先选择最直接证明验收标准的证据：

1. 端到端可观察行为。
2. 针对业务边界的集成测试。
3. 单元测试与静态检查。
4. 构建成功。
5. 人工代码阅读。

不同标准可使用不同证据；构建成功不能证明业务行为，单元测试也不能自动证明端到端连接。

## 每条验收记录

- 验收标准原文或编号。
- 验证方法与环境。
- 实际命令或操作。
- 关键输出或观察。
- `pass`、`fail` 或 `blocked`。
- 证据时间与实现版本。

## 失败规则

- 任一 must 验收失败：整体 Verification 为 failed。
- 无法运行必要环境：标记 blocked，不推断通过。
- 发现新需求：转 Change，不把它伪装成缺陷。
- 发现既有验收回归：转 Bug 或回到 execute。

## 完成规则

只有全部必需标准 pass、无未授权范围、相关回归通过，才可把 Feature 标记 `verified`。Milestone 完成还需独立检查其退出标准。
