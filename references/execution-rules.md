# 执行规则

## 开始前

- Feature 必须为 `ready`，Plan 必须为 `approved`。
- 重新读取仓库规则、Spec、Plan 和实际代码。
- 先批判性检查 Plan；发现错误先停，不盲目服从。
- 取得明确执行授权。

## 每个任务

1. 读取 `read_first`。
2. 确认任务前置已满足。
3. 观察计划要求的基线或失败测试。
4. 只修改列出的 files 和必要相邻符号。
5. 运行任务级 verify。
6. 记录事实结果与偏差，再进入下一任务。

## 允许的微调

不改变 Spec、公开接口、数据模型或影响面的明显拼写、路径纠正，可在执行记录中说明后继续。除此之外都应停止并重新计划或发起 Change。

## 必须停止

- 计划依赖、文件或接口不存在。
- 实现需要新增用户行为或扩大范围。
- 需要新依赖、数据迁移、架构决定或破坏性操作，但 Plan 未覆盖。
- 验证持续失败，且证据指向计划假设错误。
- 仓库出现与当前任务重叠的未知用户改动。

## 完成边界

Execution 完成表示：所有计划任务实施、任务级验证和计划最终验证通过，执行事实已记录。它不表示 Feature 已 `verified`。
