# 系统化调试规则

## 四个阶段

### 1. 建立事实

- 写出期望、实际、环境和最小复现。
- 找到被违反的 Spec 或已确认行为。
- 稳定复现，保存原始错误、日志与输入。
- 检查最近相关变更，但不把相关性当因果。

### 2. 定位根因

- 沿数据和控制流逆向追踪到最早错误状态。
- 在组件边界观察输入输出，不只盯最终堆栈。
- 对照同仓库工作正常的相似路径。
- 明确哪些证据支持根因，哪些只是症状。

### 3. 单一假设

- 一次提出一个可证伪假设：“因为 X，所以 Y；若为真，实验 Z 应出现结果 R”。
- 用最小实验验证，不同时改多个变量。
- 假设失败就撤销实验改动，回到证据。

### 4. 最小修复与回归

- 先用测试或确定步骤捕获失败。
- 只修根因，不顺手重构相邻代码。
- 运行失败用例、相关回归和必要构建。
- 记录根因、修复与证据。

## 三次失败规则

三次相互独立的修复尝试都失败时，停止继续打补丁。重新检查：

- 问题是否其实是新需求；
- 系统边界或数据权威是否理解错误；
- 多组件共享状态是否导致架构性耦合；
- 复现是否遗漏关键环境变量。

此时向用户报告证据与架构疑点，再决定 Change、ADR 或进一步调查。
