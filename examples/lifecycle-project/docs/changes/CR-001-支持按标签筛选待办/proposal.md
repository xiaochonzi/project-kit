# 支持按标签筛选待办

## 背景与问题

待办已经保存标签 ID，但列表命令只调用 `listTodos()` 返回全部待办，用户无法利用已有标签缩小结果范围。直接证据是命令入口没有标签参数，列表模块也没有筛选分支。

## 证据快照

- EVD-01：`listTodos()` 当前只返回完整列表，命令入口没有标签参数；该代码事实证明已有标签数据尚未形成可用的筛选能力。

## 期望结果

用户可以通过可选的标签 ID 筛选待办；未提供标签时保持现有完整列表行为。

## 包含

- 列表查询支持可选标签 ID。
- 命令行入口提供 `--tag <tag-id>`。
- 覆盖有匹配、无匹配和未传标签三种结果。

## 不包含

- 不新增标签管理、创建或编辑能力，因为本 Change 只消费已有标签。
- 不改变待办或标签的数据结构。

## 影响范围

影响列表查询模块、命令行参数解析和对应测试；不影响数据模型、权限、配置或其他命令。

## 决定

### 已确认选择

- DEC-01：使用已有标签 ID 做精确匹配；`--tag` 为可选参数，省略时保持现有输出。

### 未采用方向与原因

不支持标签名称模糊匹配，避免在本 Change 中引入名称冲突和新的查询语义。

## 未决问题

无
