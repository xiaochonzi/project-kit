# 支持按标签筛选待办

## 术语与业务对象

- 标签 ID：待办中已有的稳定标签标识；本 Change 不定义标签名称匹配。
- 未筛选：调用方没有提供标签 ID，列表返回全部待办。

## 问题与依据

待办已经保存标签 ID，但当前列表命令和 `listTodos()` 没有筛选输入，用户只能看到完整列表。

## 目标

列表查询接受可选标签 ID，并在不改变未筛选行为的前提下返回精确匹配结果。

## 用户流程

1. 用户运行列表命令，可选择传入 `--tag <tag-id>`。
2. 未传标签时返回全部待办。
3. 传入标签时只返回包含该标签 ID 的待办。
4. 没有匹配项时返回空列表，由现有列表渲染显示空态。

## 范围

### 包含

标签 ID 精确筛选、可选 CLI 参数和三种结果的自动测试。

### 不包含

标签名称搜索、标签管理、数据迁移和 UI 变更；这些都不是本次筛选契约所必需。

## 输入与输出

- 输入：可选字符串 `tagId`；省略表示未筛选。
- 输出：保持原有顺序的待办数组；筛选时数组中每项都包含完全相同的标签 ID。
- API / 事件：不涉及网络 API 或事件。

## 业务规则

- BR-01：提供标签 ID 时，只返回 `todo.tagIds` 包含该 ID 的待办。
- BR-02：未提供标签 ID 时，返回与变更前相同的完整列表和顺序。
- BR-03：没有匹配项时返回空数组，不回退到完整列表，不报错。

### REQ-01：按标签 ID 筛选待办

- Current：列表查询没有筛选输入，始终返回全部待办。
- Trigger：调用方提供可选标签 ID 运行列表查询。
- Target：提供标签 ID 时精确筛选；未提供时保持完整列表；无匹配时返回空数组。
- Business Rules：BR-01、BR-02、BR-03
- Acceptance：AC-01、AC-02、AC-03

## 失败与边界情况

- 空字符串按“未提供标签 ID”处理，执行 BR-02。
- 未知标签 ID 返回空数组，执行 BR-03。
- 待办没有 `tagIds` 或其值为空数组时，不匹配任何标签。
- 本变更不涉及权限、并发、重试、超时、状态迁移或旧数据迁移。

## 禁止事项

- 不得把未知标签回退为完整列表。
- 不得改变未筛选列表的顺序。
- 不得用标签名称、前缀或大小写转换替代标签 ID 精确匹配。

## 验收标准

- [x] AC-01：给定两个标签不同的待办，使用其中一个标签 ID 查询时只返回匹配待办。
- [x] AC-02：省略或传入空标签 ID 时，返回与变更前相同的完整有序列表。
- [x] AC-03：传入不存在的标签 ID 时返回空数组且命令正常结束。
